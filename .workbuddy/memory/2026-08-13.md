## ClipboardxAI docs site — build fix + full i18n localization

### Build failure root cause (RESOLVED)
`vitepress build docs` failed at "rendering pages" with two symptoms:
1. `ENOENT ... .temp/ja_index.md.js` (non-DEBUG only)
2. `TypeError: Cannot read properties of undefined (reading 'eyebrow')` (real crash)

- **Real cause**: `docs/.vitepress/theme/MarketplaceView.vue` rendered `content.hero.eyebrow`,
  but the marketplace frontmatter stores `marketplace.eyebrow` **flat** (no `hero` wrapper).
  Every marketplace page crashed in SSR. The `ja_index.md.js` ENOENT was a *secondary* artifact:
  when the build aborts (tempDir rimraf'd in `finally`), a concurrently-rendering page fails to
  load its module. With `DEBUG=1` the rimraf is skipped, so only the `eyebrow` error shows —
  confirming it is the primary failure.
- **Fix**: changed the 3 hero lines in MarketplaceView.vue to `content.eyebrow / content.title /
  content.desc` (flat).
- Also reconstructed `docs/ja/index.md` fully — a prior test overwrite had truncated it to a
  minimal hero+1-feature version with NO frontmatter, which would crash AdvancedHome
  (`content.sections.*` undefined).

### Debugging trick (reusable)
Run `DEBUG=1 npx vitepress build docs` to stop `.temp` from being rimraf'd, then inspect
`.temp/app.js` at the stack line for the *actual* SSR error. The ENOENT for `.temp/*.md.js`
during a non-DEBUG render is usually a downstream symptom of an earlier page crash, not the root.
